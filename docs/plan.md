# 첫 버전 계획: 창원 청년 지원사업 맞춤 매칭

> 작성일: 2026-10-30 · 기준: PRD.md v2의 핵심 시나리오(4장)와 완료 기준 1~5번(7장)

## 1. 화면 2개

| 화면 | 사용자가 하는 일 |
|---|---|
| **① 찾기·결과 화면** | 나이를 입력하고 거주지·현재 상태·관심 분야를 고른 뒤 '찾기'를 누른다. 같은 화면 아래에 결과 목록이 나온다(해당됨 → 확인 필요 → 해당 안 됨). 그 아래에 "2026년 접수 마감" 구역이 있다. 화면 맨 아래에 데이터 기준일이 보인다. |
| **② 상세 화면** | 결과에서 사업 하나를 누르면 열린다. 판정과 이유, 추가로 확인할 조건, 신청기간·방법, 필요서류, '공식 공고 보기'를 확인하고, 뒤로 가기로 결과 화면에 돌아간다. |

- 입력과 결과를 한 화면에 둔 이유: 휴대폰에서 누르는 횟수를 줄이고, 화면 수를 2개로 맞추기 위해서다.

## 2. 데이터 흐름

```
엑셀 11건 → Supabase 표(programs) → 서버 함수(api/) → 화면
```

**Supabase에 넣기로 한 이유 (API를 바로 부르지 않는 이유)**

1. 온통청년 API가 아직 '신청' 상태라 지금은 부를 수 없다.
2. API 응답에 나이·소득·신청기간 항목이 있는지 아직 확인하지 못했다.
3. PRD의 차별점이 '데이터 신뢰성'이다. 화면에는 사람이 공고와 대조한 값만 나와야 하므로, 정리한 표를 쓴다.
4. 데이터를 고칠 때 Supabase 표에서 값만 바꾸면 된다. 화면 코드는 다시 만들 필요가 없다.

**서버 함수 2개**

| 함수 | 하는 일 |
|---|---|
| `api/search` | 입력 4개를 받아 Supabase에서 사업을 읽고, PRD 4-2 판정 규칙을 적용해서 '모집 중'과 '마감' 목록으로 나눠 돌려준다 |
| `api/program` | 사업 ID 하나를 받아 상세 화면에 필요한 내용을 돌려준다 |

- **키 관리:** Supabase 키는 서버 함수에서만 쓴다. 화면 코드에는 어떤 키도 넣지 않는다.
  - 키 이름: `SUPABASE_URL`, `SUPABASE_SECRET_KEY` (서버 함수의 환경 변수에 저장)
- **원본이 바뀔 때:** 1회차 전까지는 남은 7건을 공고와 대조하면서 엑셀을 고치고, 고친 엑셀을 Supabase에 다시 넣는다. 1회차부터는 Supabase 표에서 바로 고치고, 엑셀은 더 이상 원본으로 쓰지 않는다.
- **판정을 서버 함수에서 하는 이유:** 규칙이 한 곳에만 있어야 틀렸을 때 원인을 찾기 쉽다(PRD 5장 "결과가 항상 같고 틀렸을 때 원인을 찾을 수 있음").

## 3. AI 기능

- **핵심 시나리오에는 없다.** PRD v2에서 AI 쉬운 설명을 '시간이 남으면'으로 옮겼다.
- 판정 이유 문장은 규칙 코드가 정해진 틀로 만든다(예: "나이 40세 → 조건 19~39세 불충족").
- 나중에 추가할 때는 OpenRouter를 서버 함수에서 부르고, 데이터에 있는 내용만으로 문장을 만들게 한다(PRD 5장 AI 사용 원칙).

## 4. 단계별 순서

| 순서 | 할 일 | 확인할 완료 기준 |
|---|---|---|
| 0 | Supabase 프로젝트 만들기, 엑셀 `사업목록` 시트를 programs 표로 옮기기 | 표에 11건이 들어갔는지 |
| 1회차 | ① 찾기·결과 화면 + `api/search` + 판정 규칙 | 1, 2, 5번 |
| 2회차 | ② 상세 화면 + `api/program` + 배포 | 3, 4번 |

- 배포할 곳: api/ 폴더 구조를 그대로 쓸 수 있는 곳(예: Vercel)을 가정했다. 수업에서 정한 곳이 있으면 그걸 따른다. (**확인 필요**)

## 5. 나중에 (이번에 만들지 않음)

- AI 쉬운 설명(OpenRouter)
- 온통청년 API 연동 (승인 후 응답 항목 확인부터)
- 데이터를 14일 이상 갱신하지 않을 때 경고
- 소득·주거 형태·가구 형태 입력, 주거·창업 시나리오
- 관심 분야 '교통', 거주지 구 단위 선택
- 경남도·정부 주관 사업 추가
- '참고 자료(공식 공고 아님)' 표시 확인
- 로그인·회원가입, 관리자 화면, 알림 (PRD 10장에서 제외한 것)

## 6. 처음 볼 가능성이 큰 기술: 서버 함수(api/)

화면에서 Supabase를 바로 부르지 않고, 중간에 **내 서버에서 도는 작은 함수**를 두는 방식이다.

- **키를 숨길 수 있다.** 화면 코드는 누구나 볼 수 있지만, 서버 함수 코드는 사용자에게 보이지 않는다.
- **판정 규칙을 한 곳에 모을 수 있다.**

## 7. 슬라이드 확인표 점검

| 확인할 것 | 결과 |
|---|---|
| 로그인·관리자 화면·회원가입이 들어 있다 | 없음 (5장 '나중에' 목록에 있음) |
| 화면이 3개 이상이다 | 2개 |
| API 키를 화면 코드에서 쓴다 | 서버 함수에서만 사용 |
